# Data: what is included, and how to rebuild what is not

## Included

- **Items.** All items are generated by the code: the two-hop city questions from the gazetteer in `code/cities.py` (written for this study, no download), the two-digit multiplication items, and the multiple-choice control questions in `code/mcq.py`. No third-party dataset is used.
- **Summaries and per-item results** of every stage, as JSON under `res*/`, `stage0/`, `stage0b/` and `audit/`.
- **Diagnostic logs** in `diag/` and the Stage 0b logs, which the paper cites.

## Only on Zenodo

The JSON result files larger than 2 MB are in `code-and-data.zip` on Zenodo, not in git: `res_v2/premise.json` and the seven `res_v3/eval_*.json` files. `strip_report.json` lists them under `zenodo_only`. `code-and-data.zip` holds this whole repository plus those files.

## Withheld, and how to rebuild

| Files | Why | How to rebuild |
|---|---|---|
| `*.pt` (LoRA adapters `lora_*.pt`, injection vectors `jvec.pt`) | 287 MB in `res_v3/` alone, and the code-test folders hold more. They are model weights, not evidence. | The training stages write them again (`code_v3/job_v3.py`, and `code/job.py` for v1's self-test). |
| Stage 0a and 0b hidden-state features (`feats*.pt`) | Stored outside the study folder during the runs | `stage0/s0a_extract.py` and `stage0b/s0b_extract.py`, with `S0_FEAT` and `S0B_FEATDIR` set to where they should go |
| `logs/` (job logs) | Operational output of the GPU-lock wrapper; no results | Not needed |
| `tools/gpu_lock.py` | The lab's shared GPU-lock wrapper; not part of the study | Not needed; call the stage scripts directly |

None of the withheld files is named in a `PREDICTIONS*.sha256` file. Every freeze hash verifies from this repository except the study README's line in `PREDICTIONS.sha256`; see the README, "Verifying the freezes".

## What the release filter changed

- **Model-written text.** Every JSON file was checked. The model's free-text answers in the item screens (`free1_text`, 1,116 entries in `res/screen.json` and the code-test file `res_tiny/screen.json`) were removed; no analysis reads them, and the parsed fields next to them are kept. Any other string longer than 40 characters had to be analysis text, a rule description or one of the study's own quiz questions, or the build stopped. Counts are in `strip_report.json`.
- **User folder.** In files that are not hashed, the local Windows user folder in paths is replaced by `<user>`. The hashed run scripts (`code/run_chunks.sh`, `code/tiny_*.sh`, `code_v2/run_v2.sh`, `code_v3/run_v3.sh`) keep the original interpreter path so that their hashes verify.
- **Formatting.** JSON files that are not hashed were rewritten with one-space indentation; their content is unchanged apart from the removals above.
